# 本地管理服务接入用户已有的编码 Agent

本项目的管理服务运行在用户本地，提供可视化界面，接入用户已有的编码 Agent。用户在本地管理授权和部署状态，应用资源运行在其云账号中；作者不运营集中式用户资源管理实例。此选择降低作者的持续托管负担，避免集中持有用户凭证，同时通过网页界面提供操作便利。

首版沿用外部编码 Agent，本地网页用于设置及查看资源、状态和日志，不内置聊天 Agent。此选择把首版投入集中在跨平台部署与运维。

2026-09-16 交互形态补充确认：首批目标用户为已经使用编码 Agent、能开发项目但不熟悉云部署的开发者。提供一个本地工具，以 CLI 暴露已支持的明确操作，配套薄 Skill 指导已有 Agent 使用，并以本地网页承接引导与可视化管理；各入口复用同一套执行、状态及授权检查逻辑。Agent 不可用时，用户仍可直接执行已支持的部署、更新、查询和恢复操作，复杂分析可以由人工完成；这不要求每项操作都有网页按钮。此选择增加了执行工具的维护责任，但避免把资源管理能力绑定到某次对话或某个模型。

首版安装体验为安装一个本地工具，通过一条启动命令打开网页，再由引导完成供应商授权和 Agent 接入。具体分发包、支持的本机操作系统和通信协议在实现评估阶段明确。

交互形态第二轮已确认：网页承担账号接入引导、项目与资源查看、脱敏日志，以及基于已有配置的更新和经过状态核对的重试等少量常用操作；首次接入和复杂调整主要通过 Agent 或 CLI 完成。首版优先接入能在用户本机访问已授权项目目录并执行 CLI 的 Agent，先完整验证一种接入，再逐步扩大兼容范围；模型服务可以在云端，远程执行工具的 Agent 接入后置。

首版接受本地编排中断，不提供退出工具后仍常驻协调任务的后台服务。关闭网页不取消仍在本地服务中执行的任务；退出本地执行进程后，尚未执行的本地步骤暂停，已提交的云端任务由供应商处理。重启后读取操作记录并核对云端实际结果，再提示用户继续或重试，不能把结果未知直接认定为失败并重复创建资源。此取舍优先保证中断后可理解、可恢复，代价是部分流程需要用户重新打开工具才能完成；已上线应用继续由云平台运行。

2026-09-16 补充确认：核心操作不依赖作者运营的在线后端，不要求登录作者账号；本地持有的资源凭证、项目状态和操作记录由用户掌控。曾考虑作者统一分配子域名以降低上手成本，但这会集中域名控制权和持续运营责任；首版采用服务商地址或用户自有域名，作者域名仅用于自己的官网、文档、下载与演示。未来在线协作等便利服务可以单独评估，但不能成为核心功能的强制依赖。

验收时，在本地工具已安装、用户供应商授权有效且供应商服务可达的条件下，阻断作者运营的后端，仍应能够完成预检、部署、更新、查询状态和日志、恢复以及约定范围内的迁移。这一要求约束对作者服务的依赖，不意味着无需联网或无需第三方云服务。
